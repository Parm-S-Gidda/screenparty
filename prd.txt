# PRD: AI-Hosted Browser Party Game Platform

## 1. Product Summary

This product is a Kahoot/Jackbox-style browser game platform where one person hosts a game on a shared main screen, and players join using their phones through a room code.

The platform will support multiple party/classroom/bar-style games over time, but the MVP will focus on one polished game: **Buzz-in Trivia**.

The main differentiator is a **virtual AI host** that controls the flow of the game, reads questions, reacts to players, judges typed answers, and creates a funny PG-safe game show experience using an LLM and ElevenLabs voice.

Only hosts need accounts. Players do not need accounts.

---

## 2. Product Goals

### Primary Goals

* Build a fast, fun, real-time browser game experience.
* Let players join easily with a room code and phone.
* Let hosts configure and launch games from a main screen.
* Support both **Self Host** and **Virtual AI Host** modes.
* Build a flexible architecture where new games can be added later.
* Keep costs controlled through plan limits, rate limits, and AI usage caps.
* Launch with one strong MVP game before expanding.

### Business Goals

* Offer a limited free tier.
* Monetize through subscriptions.
* Make AI hosting a paid feature.
* Support parties, classrooms, friends, bars, and remote Discord screen-share play.

## 6. Core User Flow

### Host Flow

1. Host signs in.
2. Host clicks “Create Game.”
3. Host selects a game.
4. Host configures game settings.
5. Host launches room.
6. Main screen shows room code.
7. Players join using their phones.
8. Host starts game when ready.
9. Game runs through Self Host or Virtual Host mode.
10. Final podium appears with winners.

### Player Flow

1. Player goes to join page.
2. Player enters room code.
3. Player enters username.
4. Player selects avatar.
5. Player enters lobby.
6. Player waits for game to start.
7. Player uses phone as controller during game.
8. Player sees score, place, and game state.
9. Player leaves after game ends.

## 9. Buzz-in Trivia Game Flow

### Self Host Mode

1. Main screen says waiting for host.
2. Host phone shows preview of next question.
3. Host taps “Display Question.”
4. Main screen displays the question.
5. Buzzing opens.
6. Players buzz using their phones.
7. Main screen shows buzz animation and first buzzer.
8. Player answers out loud.
9. Host marks answer as Correct or Incorrect.
10. If correct:

    * points are awarded
    * correct animation plays
    * answer is revealed
    * scoreboard appears
11. If incorrect:

    * incorrect animation plays
    * if retries are on, next buzzer gets a chance
    * if retries are off, answer is revealed
12. Game moves to next question.
13. Final podium appears at game end.

### Virtual Host Mode

1. AI host starts the game with a short intro.
2. AI host introduces or reads the question.
3. Main screen displays the question.
4. Buzzing opens.
5. Player buzzes.
6. AI host reacts to player buzz.
7. Player types answer on phone.
8. System checks answer locally first.
9. If ambiguous, LLM judges if answer is close enough.
10. AI host says a funny PG-safe correct or incorrect line.
11. Answer is revealed.
12. Scoreboard appears.
13. AI host continues to next question.
14. Final podium appears at game end.

## 11. Host Controller Architecture

The system should not build two separate versions of the same game.

Instead, build:

```text
Trivia Game Engine
SelfHostController
VirtualHostController
```

The game engine owns:

* game state
* scoring
* buzz order
* question index
* player state
* answer reveal
* game completion

The controller owns:

* who advances the game
* when host lines are played
* whether answers are typed or spoken
* whether answer judging is manual or automatic

## 13. Voice System

The virtual host will use ElevenLabs for voice.

### Voice Strategy

Use a hybrid voice system:

```text
Pre-generated common lines
Live-generated player-specific lines
Cached voice clips
```

### Pre-Generated Examples

```text
Welcome to the game.
Here comes the next question.
Time is up.
Let's check the scores.
Final question.
Game over.
```

### Live-Generated Examples

```text
Parm buzzes in like he has been waiting his whole life for this.
Sarah got it right and now everyone else is suddenly nervous.
```

### Voice Requirements

* Every generated voice line should be cached.
* Common lines should never be regenerated repeatedly.
* Main screen should show captions.
* Main screen should allow skipping voice playback.
* Host line length should be capped.
* AI voice usage should be tracked per account.

## 14. Answer Judging

Virtual Host mode requires typed answers.

### Judging Pipeline

1. Normalize user answer.
2. Check exact match locally.
3. Check accepted answers locally.
4. Run local fuzzy comparison.
5. If still ambiguous, call LLM judge.
6. Store result.
7. Award points if correct.

### Local Normalization

Normalize by:

```text
lowercasing
trimming whitespace
removing punctuation
removing extra spaces
optionally removing "the", "a", "an"
```

### LLM Fallback

The LLM should only be used when the local system is unsure.

Prompt goal:

```text
Given the question, correct answer, accepted answers, and player answer, decide if the player answer should count as correct.
Return only correct or incorrect.
```

### Stored Result

Each answer should store:

```text
submitted_answer
judged_result
judged_by
confidence
player_id
question_id
created_at
```

Possible `judged_by` values:

```text
local_exact
local_accepted_answer
local_fuzzy
llm
manual_host
```

## 15. Buzz Order Retries

If Buzz Order Retries are enabled:

1. Server records buzz order.
2. First buzzer answers.
3. If wrong, the next buzzer gets a chance.
4. Repeat until max retries are reached.
5. Max retries should be capped at 5.
6. If no one gets it correct, reveal answer.

### Buzz Storage

```text
buzzes
- id
- session_id
- question_id
- player_id
- server_received_at
- buzz_order
- used_attempt
```

The server must use server time, not player device time.

---

## 16. Scoring

Default scoring:

```text
First correct answer: 100 points
Second retry correct: 75 points
Third retry correct: 50 points
Fourth retry correct: 25 points
Fifth retry correct: 10 points
Wrong answer: 0 points
No answer: 0 points
```

This can be adjusted later.

### Required Limits

```text

max custom question length
```

### Moderation Required For

```text
usernames
typed answers
custom questions
AI-generated questions
AI host output
anonymous submissions in future games
```

### Anti-Abuse Rules

* host must be authenticated
* players use temporary session IDs
* room codes expire
* kicked players cannot rejoin with same session
* rate limit buzz attempts
* rate limit answer submissions
* rate limit room creation
* rate limit AI requests
* never trust client timestamps
* never expose hidden answers to players
* validate all game actions server-side

## 25. AI Question Generation

Paid users can generate a pack before the game starts.

### Flow

1. Host selects topic.
2. Host selects difficulty.
3. Host selects number of questions.
4. Server checks subscription and usage.
5. Server sends controlled prompt to LLM.
6. LLM returns structured JSON.
7. Server validates questions.
8. Server stores questions privately.
9. Game starts.

### Required Question Format

```json
{
  "question": "What planet is known as the Red Planet?",
  "answer": "Mars",
  "acceptedAnswers": ["mars", "the planet mars"],
  "difficulty": "easy"
}
```

### Rules

* no hints
* no explanations
* no offensive content
* no duplicate questions in same pack
* no answer sent to player devices before reveal
* generated questions should be stored only server-side

## 29. Future Game Concepts

### Majority Would You Rather

Players guess what the majority or selected player will choose.

For teams:

* players guess what the other team will choose
* points awarded for correct prediction

### Two Truths and a Lie

A player submits two truths and one lie. Other players guess the lie.

Variation:

```text
Two Lies and a Truth
```

### Who Did It

Players anonymously submit something they have done or think. The group guesses who submitted it.

This game will require stronger moderation because of anonymous input.
